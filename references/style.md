# 写作规范与可用格式

skill 流程和 Outlook 里的「AI 答复」按钮共用这份规范（`scripts/ai_reply.py` 会把它和 `templates.md` 一起放进提示词）。

## 写作规范

**先定类型，再定长度。** 确认类 2–4 行；逐条答复按问题数；状态 / 技术问题才用小标题和表格。能 5 行说完不写 10 行，一般回复正文 ≤ 15 行。

1. **称呼**：沿用线程里的叫法；默认 `Hi 名字`，多人 `Hi all`；对客户、上级可用 `X总，您好`。名字取收件人的显示名（中文名优先），取不到用对方签名里的称呼。
2. **结论先行**：称呼后的第一句就是答复本身（同意 / 不同意 / 已完成 / 什么时候给）。三段以上的长邮件，把结论放进 `>` 结论框。
3. **结构按内容长**：
   - ≥2 个并列点用列表；对方有编号就沿用对方编号和顺序。
   - ≥3 项、每项 ≥2 个属性（状态、负责人、时间…）用表格。
   - ≥3 个主题才用 `##` 小标题；短邮件不加标题、不加结论框。
4. **行动项写全**：谁 + 做什么 + 截止日期。日期写绝对日期加星期，如 `10月28日（周三）`；不单独写"尽快 / 近期 / ASAP"。需要对方做的事放在最后单独成段（`**需要您**` 或 `**需要支持**`）。
5. **语言跟随原邮件**：英文来信英文回。中英混排保留原术语和大小写（SoC、OTA、Android 14），中文与英文 / 数字之间加空格。
6. **语气**：平实、专业、对事不对人；对客户和上级用"您"。不用感叹号，不用 emoji（状态表格里的 🟢🟡🔴 除外）。不写套话结尾（"如有问题随时联系""希望对您有帮助""辛苦了~"）。不用"值得注意的是 / 总的来说 / 综上所述 / 首先…其次…最后 / 赋能 / 抓手"，不堆破折号，不硬凑三点。
7. **事实纪律**：答复里的日期、数字、结论、承诺只能来自用户给的要点或邮件原文，不编造，不替用户承诺。拿不准的写 `【待确认：xxx】`，渲染时标红，由用户补全。
8. **收件人**：原邮件有抄送或多个收件人默认全部答复；只涉及发件人或内容敏感时单回。
9. **主题**：保持 `RE: 原主题`，正文里不写主题。
10. **署名**：`BR` 和签名行由 render.py 按「设置」里的签名和结束语自动追加，正文里不要再写。

## 可用格式（render.py 支持的 Markdown 子集）

| 写法 | 效果 |
|---|---|
| 空行 | 分段；段内换行原样保留 |
| `## 小标题`（`#` / `###` 也可） | 带左侧色条的小节标题 |
| `- 项` / `1. 项`，缩进 2 空格嵌套 | 列表；`3.` 开头会从 3 开始编号 |
| `\| 表头 \|` + `\|---\|` | 带边框表格；`:---:` 居中；单元格内换行写 `<br>` |
| 单元格只写状态词 | 自动着色：已完成 / 通过 / OK → 绿；进行中 → 蓝；风险 / 延期 / 阻塞 / NG → 红；待定 / 待确认 / 未开始 → 黄 |
| `> 文字` | 浅底结论框（框内可含列表） |
| `**加粗**`、`==高亮==`、`~~删除~~`、`` `代码` `` | 行内样式 |
| `[文字](https://…)`、裸 URL | 链接 |
| ` ``` ` 代码块 | 等宽浅底块，适合贴日志、命令 |
| `---` | 分隔线 |
| `【待确认：…】` | 红底标记，提醒补全 |

不支持斜体和图片。
