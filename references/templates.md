# 回复模板

挑最贴近的一个骨架，删掉用不上的部分。骨架是结构参考，不是必填表；短邮件就写短。
署名（`BR` + 签名）由 render.py 自动追加，正文里不要写。

## 选型

| 场景 | 判断依据 | 骨架 |
|---|---|---|
| 确认 / 收到 | 对方只需知道"收到、会做、何时" | A |
| 逐条答复 | 对方提了 ≥2 个问题或编号列表 | B |
| 进度 / 状态同步 | 汇报多个事项的状态 | C |
| 技术问题 / Bug 答复 | 对方问原因、方案、修复时间 | D |
| 请求支持 / 请对方决策 | 需要对方给资源、信息或拍板 | E |
| 婉拒 / 延期 / 推回 | 不能按对方要求做 | F |
| 会议 / 沟通结论同步 | 把线下沟通结论落成邮件 | G |

---

## A. 确认 / 收到

```markdown
Hi 张伟

收到，我们 10月28日（周三）前给出评估结果。
期间如果需求有变化，直接回这封邮件同步即可。
```

## B. 逐条答复

对方有编号就沿用对方的编号和顺序；没有编号就按对方提问顺序编号。每条先给答案，再给依据。

```markdown
Hi 老陈

几个问题统一回复如下：

1. **是否需要驻场**：默认不需要；客户明确要求时再安排，费用另议。
2. **新版本切换时间**：1.0 交付后 2 个月内完成，量产节点 2027年6月不变。
3. **能否用闭源库**：不可以。客户要求源码交付，必要时自研替换。

第 2 点依赖供应商释放新版 SDK，时间有变化我再同步。
```

## C. 进度 / 状态同步

≥3 个事项用表格。状态列用固定词（已完成 / 进行中 / 风险 / 待确认），渲染时自动着色。

```markdown
Hi all

> 本周整体按计划推进，**内存优化存在延期风险**，需要平台组 10月30日前给出内存方案评审结论。

| 事项 | 状态 | 负责人 | 计划完成 | 备注 |
|---|---|---|---|---|
| 1.0 基线交付 | 已完成 | 张三 | 10月20日 | 已提测 |
| 启动时间优化 | 进行中 | 李四 | 11月05日 | 当前 28s，目标 20s |
| 内存占用优化 | 风险 | 王五 | 11月15日 | 等平台评审 |

**需要支持**
- 平台组：10月30日（周五）前给出内存方案评审结论
```

## D. 技术问题 / Bug 答复

```markdown
Hi 李工

> 问题已定位，是 system_server 在音频焦点切换时持锁超时导致的 Watchdog 重启，修复版本预计 10月29日 提测。

## 现象
导航播报时切换音乐，约 1/50 概率黑屏重启（PROJ-1024）。

## 原因
`AudioService` 在焦点回调里同步等待 HAL 返回，HAL 侧阻塞 > 60s 触发 Watchdog。

## 方案
1. 焦点回调改为异步投递，不再在 binder 线程上等待 HAL
2. HAL 侧增加 3s 超时保护

## 计划
| 节点 | 时间 |
|---|---|
| 修复合入 | 10月28日 |
| 提测 | 10月29日 |
| 回归结论 | 10月31日 |
```

## E. 请求支持 / 请对方决策

先一句背景，再说清楚要什么、给出选项和建议、截止时间。

```markdown
Hi 王总

X 项目需要在 11月01日 前确认人力投入，请您从以下两个方案中拍板：

| 方案 | 人力 | 周期 | 风险 |
|---|---|---|---|
| 1. A 团队独立承接 | 8 人 | 6 个月 | 没做过这个平台，前期效率低 |
| 2. A + B 团队联合 | 10 人 | 5 个月 | 跨地协作成本 |

**建议选方案 2**：B 团队做过同平台项目，可以把前两个月的平台适配风险降下来。

请在 10月30日（周五）前回复结论，我们据此排期。
```

## F. 婉拒 / 延期 / 推回

结论放第一句，原因讲客观事实，一定给替代方案或新时间。

```markdown
Hi 张伟

多路视频加水印放在 Android 侧实现，我们评估下来不建议，原因是 Android 侧 CPU 余量不足 20%，叠加后会影响投屏场景的流畅度。

建议改为 Linux 侧实现，Android 侧只做预览和回放。如果确认按这个方向，我们 11月05日 前给出接口方案。
```

## G. 会议 / 沟通结论同步

```markdown
Hi all

今天和合作方完成了沟通，结论同步如下，如有出入请直接回复更正。

## 结论
1. X 项目 Android 14 / 16 双基线并行：先交付 Android 14，2 个月内切 Android 16
2. 需完成内存、启动时间、70% 资源上限三项优化

## 待办
| 事项 | 负责人 | 截止 |
|---|---|---|
| 内部评估人力 | 合作方 | 10月25日 |
| 确认投入与排期 | 我方 | 10月28日 |
```
